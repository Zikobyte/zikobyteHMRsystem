1. Project Overview

Purpose

ZMC EHR (Zikora Medical Centre Electronic Health Record) is an intranet-hosted, browser-based hospital management system built for Zikora Medical Centre, Ogborhill, Aba, Abia State, Nigeria. It replaces paper-based patient records and cash tracking with a real-time, multi-department digital workflow that requires no internet connection — all data, communication and notifications flow over the hospital's local area network (LAN).

Main Workflows

  • Regular OPD: Register → Vitals (Nursing) → Cashier (₦5,000 fee) → Doctor → [Lab payment → Lab → Doctor] → Cashier (Pharmacy) → Pharmacy → Complete
  • Emergency: OPD collects cash (records Total Bill + Collected + Balance) → Doctor immediately → Cashier confirms receipt → Regular flow
  • Maternity/Antenatal: Registration → Cashier → Doctor → [In labour → Maternity Ward → Delivery → Cashier] or [Routine visit → continue]
  • Walk-in Lab: Lab registers → Cashier verifies → Lab runs tests → Results collected
  • Admission: Doctor marks pending → OPD 4-group view → Nursing assigns ward/bed → Daily care loop → Doctor discharges → Bill auto-sent to Cashier → Settled → Discharged
  • Discount Approval: Cashier selects patient bill → enters amount + reason → HR reviews → Approve/Reject → Account Officer logs
  • Procurement: Pharmacist requests → Account Officer reviews → HR approves → Supplier delivers
  • Eye Clinic: Registration → Consultation → Service selection → Cashier → Complete

    • Navigation Structure

    • Single-page app — all routing via React state (activeTab / role-based conditional rendering)
    • Top header bar with role display, report buttons (Storage Report, Intranet Guide), Process Flow, and Logout
    • Role determines which interface component renders
    • No URL-based routing (localStorage-persisted sessions)

    Screen Hierarchy

    `` App ├── LoginScreen (no user) └── MainApp (logged in) ├── Header (all roles) │ ├── Storage Report overlay │ ├── Intranet Setup Guide overlay │ └── Process Flow overlay ├── OPDInterface (role: opd) ├── CashierInterface (role: cashier) ├── DoctorInterface (role: doctor) ├── LabInterface (role: lab) ├── PharmacyInterface (role: pharmacy) ├── NursingInterface (role: nurse) ├── EyeClinicInterface (role: eyeclinic) ├── AccountOfficerInterface (role: account) └── HRInterface (role: hr) ``

    • All interfaces use mobile-first Tailwind, collapsing to single column on <768px

    • Tab bars collapse to 2-column or scroll horizontally
    • The app is primarily desktop-optimized (hospital kiosk use)

    • Scrollable lists: max-h-[calc(100vh-Xpx)] overflow-y-auto
    • Tables: overflow-x-auto wrapper
  • Main page: overflow-auto on root div

    • 4. Components

    PatientCard (inline in lists)

    • Purpose: Single-row or card entry for a patient in a list
    • Props: patient: Patient, isSelected: boolean, onClick: () => void
    • States: default, selected (border-blue-500 bg-blue-50), emergency (border-red-300 bg-red-50)
    • Contents: name (font-semibold), ID (text-xs), status badge, type badge

      • StatusBadge

    • Purpose: Pill badge showing patient status or payment state
    • Variants: 'Partial' (yellow), 'Pending' (yellow), 'EMERGENCY' (red), 'WITH DOCTOR' (blue), 'OUTSIDE LAB' (orange), 'Awaiting Nursing' (orange), 'Discharge Billing' (amber), 'Discharged' (green)
    • Size: text-xs px-2 py-0.5 rounded-full font-semibold

      • PaymentBreakdownCard

    • Purpose: Show Total Bill / Collected / Balance in 3-column grid
    • Props: totalBill, collected, balance
    • Colors: gray (total), green (collected), red if balance > 0 else green (balance)

      • SummaryStatCard

    • Purpose: Large number + label stat card (Cashier, HR, Account)
    • Props: label, value, color, onClick (optional expand)
    • States: default (border-transparent), active (border-{color}-300 shadow-md)
    • Used in: CashierInterface summary row, Admission groups, HR dashboard

      • TabBar

    • Purpose: Horizontal tab navigation
    • Props: tabs: {id, label, badge?}[], active, onChange
    • Variants: standard (bg-{color}-600 active), grid layout (col-span-*)
    • Badge: white pill with colored text for counts

      • FormField

    • Pattern: label + input/select/textarea stacked vertically
    • ``tsx
      • <div> <label className="block text-sm font-medium text-gray-700 mb-1">{label} *</label> <input className="w-full px-3 py-2 border border-gray-300 rounded-md focus:outline-none focus:ring-2 focus:ring-{color}-500" /> </div> ``

      SectionPanel

    • Purpose: White card container with title
    • Pattern: bg-white rounded-lg shadow-md p-6

      • AlertBanner

    • Purpose: Full-width colored notification at page top
    • Pattern: bg-{color}-50 border-l-4 border-{color}-500 p-4 rounded-lg
    • Contents: icon + title + description + optional action button

      • DataTable

    • Purpose: Sortable/filterable data display
    • Props: columns, rows, onRowClick?
    • Header: bg-{color}-50 or bg-gray-100
    • Row: hover:bg-{color}-50 transition, border-t border-gray-100
    • Footer: tfoot for totals row

      • DiscountRequestCard (HR Discounts tab)

    • Purpose: Display a single discount request with approve/reject actions
    • States: pending (border-amber-300 bg-amber-50 header), approved (border-green-300), rejected (border-red-200)
    • Actions: Approve button (green) + rejection reason input + Reject button (red)

      • DischargeCard (Cashier Discharge Bills tab)

    • Purpose: Patient discharge bill with itemised breakdown and payment input
    • Header: bg-green-700 with patient info
    • Body: Admission charges table + 3-stat summary + payment input

      • AdmissionGroupCard (OPD Admissions)

    • Purpose: Clickable stat card that expands to patient list
    • Props: label, count, countColor, isActive, onClick
    • Active state: border-2 border-{color}-300 shadow-md
    • Expanded panel: colored left-border panel with patient table or card list

      • CodeBlock (IntranetSetupReport)

    • Purpose: Syntax-highlighted code display with copy button
    • States: normal, copied (button text changes for 2s)

      • VitalsGrid

    • Purpose: Display patient vitals in a compact grid
    • Fields: BP, HR, Temperature, RR, SpO2, Weight, Height

      • MedicationSearch (Doctor prescription)

    • Purpose: Searchable dropdown for medication selection with auto-price fill
    • Props: index, value, onSearch, onSelect, onPriceChange
    • Behavior: Shows dropdown on focus, filters by typed text, closes on selection

      • OrderForm (Doctor admitted orders)

    • Purpose: Place medication/injection/lab orders for admitted patients
    • Type selector: 3 toggle buttons (Medication, Injection, Lab Test)
  • Dynamic body: Changes form based on type selection

    LoginScreen

    • Route: / (initial)
    • Layout: centered card, max-w-md, bg-white, shadow-lg, p-8

    • Route: / (role=opd)
    • Tabs: Regular Patient | Emergency | Returning Patient | Maternity | Admissions (badge: admitted count)
    • Regular tab: Registration form left + Recent patients list right

    • Returning tab: Search bar + matching patient cards + renewal vitals form
    • Maternity tab: Full maternity registration form (clinical + OB details)
    • Admissions tab: 4 clickable stat cards → expandable patient table/card list
    • Error state: Alert shown if required fields missing
    • Alert banners: Emergency cash pending + pending admissions count

      • Cashier Interface

    • Route: / (role=cashier)
    • Alert banners: Discharge bills pending (green), Emergency cash pending (red), Walk-in lab pending (orange)
    • Stat row: 6 cards (Pending, Discharge Bills, Outstanding, Total Patients, Revenue, Balance Day button)
    • Tabs: Pending Payments | Discharge Bills | Outstanding Balances | PV | Discounts
    • Pending: Emergency + Walk-in + Regular sections with amount inputs + live balance previews
    • Discharge: Itemised admission charges + 3-stat summary + collect/discharge button
    • Outstanding: Table with patient, owed items, total billed, paid, balance, Record Payment input
    • PV: Add PV form + PV log table
    • Discounts: Patient picker form (3 steps) + Discount requests log + Free treatment record

      • Doctor Interface

    • Route: / (role=doctor)
    • Main tabs: Out-Patient Consultations (badge: waiting count) | Admitted Patients (badge: admitted count)
    • Outpatient: Patient list (left 1/3) + Consultation panel (right 2/3)
      • - Consultation: Patient info → Vitals → Lab Results (if available) → Doctor Notes textarea → Lab test selectors → Medication prescription → Actions (Admit, Complete, Download EHR)
    • Admitted: Admitted list (left 1/3) + Detail panel (right 2/3)
      • - Detail tabs: Overview & Notes | Vitals | Medications | Observations | Charges | New Orders - Header: Patient info + Discharge button (shows bill preview amount) or "Bill Sent to Cashier" status
    • Discharge button states: Red "Discharge Patient" with ₦X bill preview → Amber "Bill Sent to Cashier" (after click) → Green "✓ Discharged" (after Cashier settles)

      • Lab Interface

    • Route: / (role=lab)
    • Tabs: Regular Patients | Walk-in Registration
    • Regular: Lab queue (waiting patients) → select → mark results → submit
    • Walk-in: Full registration form + test selection by category + fee calculation + send to Cashier

      • Pharmacy Interface

    • Route: / (role=pharmacy)
    • Tabs: OPD Dispensing | Admitted Orders | Procurement | Stock Management
    • OPD Dispensing: Patients with pharmacy_ready status → dispense confirmation
    • Admitted Orders: Medication orders from doctors for admitted patients → mark dispensed
    • Procurement: Add item form (drug name, qty, price) + submit to HR/Account
    • Stock: Drug inventory table with inline edit (dispensed, used quantities)

      • Nursing Interface

    • Route: / (role=nurse)
    • Main views: Admitted Patients | Detained Patients | Dispensing Records | Injection Records
    • Pending Admissions: Collapsible section at top — cards for each pending_admission patient with "Process Admission" button → modal (ward, bed, next of kin, religion, doctor orders)
    • Admitted detail tabs: Medications (administer) | Observations (add note) | Vitals (record) | Billing (add charges)
    • Detention modal: Reason + initial observation
    • Discharge: "Process Discharge" button when dischargeRequested=true

      • Eye Clinic Interface

    • Route: / (role=eyeclinic)
    • Tabs: Register Patient | Consultation | Patient Records
    • Register: New or returning patient, chief complaint
    • Consultation: Routine exam, external exam, service selection (checkboxes with prices), total calculation
    • Records: Searchable by card ID, view full history

      • Account Officer Interface

    • Route: / (role=account)
    • Time filters: Today | Week | Month | All
    • Report views: Overview | Doctors | Lab | Pharmacy | Procurement | Outstanding | Discounts
    • Overview: Revenue stats + bar/line/pie charts + transaction table with search
    • Doctors: Per-doctor revenue + patient counts
    • Lab: Per-lab-tech performance
    • Pharmacy: Per-pharmacist performance
    • Procurement: Procurement history table
    • Outstanding: Table of patients with unpaid balances
    • Discounts: Approved discount register + all requests log
    • Export: Excel download button on each view

      • HR Interface

    • Route: / (role=hr)
    • Alert banner: Discount requests pending (purple) at top
    • Tabs: Dashboard | Employees | Absences | Recruitment | Procurement | Discounts (badge: pending count)
    • Dashboard: Staff count stats + absence summary + procurement stats
    • Employees: List/table + Add form + Document management per employee
    • Absences: Log table with filter + Add absence form
    • Recruitment: Job requisitions + Candidates per requisition
    • Procurement: All procurement orders + approve/update status
  • Discounts: Discount request cards with Approve / Reject actions

    7. Tables

    Patient Transaction Table (Account Officer)

    • Columns: Date/Time, Patient Name, Patient ID, Type, Payment Type, Amount Billed, Amount Paid, Balance, Status, Department, Doctor/Tech/Pharmacist
    • Sorting: By date (default desc)
    • Filtering: Time filter (today/week/month/all) + search by patient name/ID
    • Pagination: None (all in scrollable div with max-height)
    • Row actions: None (read-only)
    • Selection: None

      • Outstanding Balances Table (Cashier + Account Officer)

    • Columns: Patient, What is Owed (partial payment items), Total Billed, Paid, Balance
    • Footer row: TOTALS with sum of all columns
    • Row action: Amount input + Record Payment button (inline)
    • Sorting: None
    • Search: None

      • Admitted Patients Table (OPD Admissions + Doctor)

    • Columns: Patient (name/ID/phone), Ward/Bed, Doctor, Admitted (date + days ago), Notes/Diagnosis, Type badge, Balance
    • Grouping: Separated into Currently Admitted / Maternity Ward / General Ward

      • Lab Queue Table (Lab Interface)

    • Columns: Patient name, ID, Tests ordered (with prices), Total, Status
    • Row action: Select to open result entry

      • Pharmacy Stock Table

    • Columns: Drug name, Total received, Dispensed, Used/Expired, Current stock
    • Row action: Inline edit (number inputs for dispensed/used)

      • Procurement Table (HR)

    • Columns: Date, Ordered by, Items (count), Total Amount, Status, Actions
    • Row action: Approve / mark completed (dropdown or button)

      • Discount Requests Table (Cashier Discounts tab)

    • Columns: Patient, Bill Type, Balance, Discount (₦), After Discount, Reason, Status, Date
    • Status badge: PENDING (amber), APPROVED (green), REJECTED (red)
    • Sorting: Newest first

      • PV (Payment Vitae) Log Table (Cashier)

    • Columns: PV No., Date, Person, Purpose, Amount (₦), Approved By, Delete button
    • Footer: TOTAL DISBURSED
    • Row action: Delete (Trash2 icon)

      • Nursing Charges Table (Nursing billing tab)

    • Columns: Date, Description, Category, Amount
    • Footer: Total Charged, Payments Made, Outstanding
    • Add form: Description text, Amount number, Category select, Add button

      • Employee Document Table (HR Employees)

    • Columns: Document Name, Type, File Path, Upload Date, Delete
  • Row action: Delete button

    14. Developer Notes

    Ambiguities & Implementation Decisions Required

    1. Authentication

    • Current: No real authentication — any username + role works
    • Decision needed: Implement bcrypt password verification, JWT tokens, session expiry (8h)
    • Reference: Full server.js implementation in IntranetSetupReport

      • 2. Payment Status Semantics

    • amount = total bill amount
    • amountPaid = amount actually collected so far
    • status: 'pending' = not yet collected (e.g. cashier needs to confirm emergency cash)
    • status: 'partial' = some collected, balance outstanding
    • status: 'paid' = fully settled
    • The distinction between "pending" and "partial" for emergency cash is subtle and should be well-documented

      • 3. Discharge Billing

    • Discharge payments use IDs prefixed with DISCH- for identification
    • When doctor discharges: existing pending payments are marked 'paid' (absorbed), a new DISCH- payment is created
    • Gap: If a patient has multiple pending payments (lab + pharmacy unpaid), all are absorbed. Consider whether this is the correct behavior

      • 4. Discount Application

    • HR approval updates the DiscountRequest status but does not modify the payment amount in the database
    • The Cashier sees the discount and must factor it in manually to the payment amount
    • Recommendation: When HR approves, automatically create a negative payment record or reduce the pending amount

      • 5. Maternity vs General Ward Logic

    • Maternity Ward = admitted patients where patientType === 'maternity'
    • General Ward = all other admitted patients
    • Ward name in the patient record may not contain "maternity" — typed by nurse — so the filter is by patientType, not ward name

      • 6. Emergency Cash Confirmation Logic

    • emergencyCashConfirmed: false = cash not yet confirmed by cashier
    • Even with partial payment, emergencyCashConfirmed is set to true — meaning "cashier has acknowledged"
    • The remaining balance goes to Outstanding Balances

      • 7. Lab Direct vs Regular Lab

    • patientType: 'lab_direct' = walk-in lab patient (no doctor consultation)
    • Regular patients ordered to lab have patientType: 'regular' but status: 'lab_processing'
    • Lab interface handles both but with different status transitions

      • 8. Missing Features (scope for future development)

    • Real-time notifications between departments (WebSocket implementation spec in IntranetSetupReport)
    • DICOM/radiology integration
    • Prescription printing
    • Patient portal / appointment booking
    • Biometric patient identification
    • Insurance/HMO payment processing
    • Automated medication interaction checking
    • Bulk patient import

      • 9. Performance Considerations

    • The patients array is passed to all components — with hundreds of patients this will cause unnecessary re-renders
    • Recommendation: Memoize filtered patient lists with useMemo, or migrate to server-side filtering

      • 10. Data Integrity

    • Procurement total is not recalculated if items change after submission
    • Patient ID format differs by type: REG-${Date.now()}, EMG-${Date.now()}, MAT-${Date.now()}, LD-${Date.now()}
    • No duplicate detection for patient registration

      • 11. Eye Clinic Records

    • Eye clinic has its own separate localStorage key (eye_clinic_records) and its own EyeRecord type — separate from the main Patient system
    • Charges are tracked locally in the eye clinic, not in the main payments array
    • Decision needed: Unify with main patient system or keep separate

      • 12. Nursing Dispensing & Injection Records

    • Also stored in their own localStorage keys — not linked to patient records
    • Decision needed: Link to patient admissionOrders for audit trail

      • 13. Reset Demo Button

    • Available to all logged-in users — clears ALL localStorage and reloads
    • Production: Remove or restrict to admin role only

      • 14. CONSULTATION_FEE constant

    • Hardcoded as const CONSULTATION_FEE = 5000 in OPDInterface.tsx
    • Should be moved to a config file or admin-settable value

      • 15. Medication List

    • 130+ medications hardcoded in DoctorInterface.tsx (sorted alphabetically)
  • Should be extracted to data/medicationList.ts and potentially made admin-editable
